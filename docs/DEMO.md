# Demo walkthrough

The README contains real application screenshots. A narrated video has not been published yet. This shot list is for recording an honest, short demonstration with sample files and a disposable agent project.

## 90-second overview

| Time | Show | Explain |
| --- | --- | --- |
| 0–10 s | Walk through the lounge, past the rain window and desk | “I wanted my desktop to feel like a place, rather than a grid of icons.” |
| 10–25 s | Open a chest, browse sample files, carry a link to another chest | “The chests organize real file links without moving the originals.” |
| 25–40 s | Aim at the TV; pause, resume, scroll, or search | “This is a live embedded browser, with input mapped from the 3D screen back into WebView2.” |
| 40–65 s | Address a villager, review a task, send it, and show the workstation producing a small file | “The character represents a persistent Codex agent session. I built the session, status, screen, and input integration.” |
| 65–80 s | Open the resulting file, then return to the cave and application dock | “It works with the actual Windows desktop, so the output is useful outside the world.” |
| 80–90 s | End on the room and repository URL | “Built with C#, Godot, Windows APIs, WebView2, and Codex, using an AI-assisted development workflow.” |

Use an agent task such as “Create a three-item project checklist in demo-notes.md in this empty demo folder.” Show the actual result, and label any time cut while the agent is working. If microphone capture is unreliable, use typed input and identify voice as an optional feature.

## Recording and publishing

- Use sample documents and an isolated project, with notifications off. Check visible filenames, browser account details, transcript text, and Windows previews before publishing.
- Play a video you own or have permission to show. Leave Minecraft music off for the recording.
- Record actual interaction; confirm the capture advances during gameplay and that the pointer is visible. Recording compatibility has needed testing in this prototype.
- Upload the finished demo to a shareable video page, then link its real URL above the first README screenshot. Do not label still screenshots as a playable demo.
- Add captions so reviewers can understand the project with sound off.

A short overview should lead the README. A separate, longer technical walkthrough can explain browser input mapping, agent lifecycle, and save recovery for engineering interviews.
